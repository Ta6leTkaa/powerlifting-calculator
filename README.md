# Powerlifting Bot

Telegram-бот: профиль → запись силовых результатов → история с баллами Wilks.
Отдельные категории: присед, жим, тяга и троеборье.

## Запуск через Docker

1. Создайте бота у [@BotFather](https://t.me/BotFather) и получите токен.
2. Скопируйте настройки: `cp .env.example .env`.
3. Укажите токен в `BOT_TOKEN` в `.env`. Не публикуйте этот файл.
4. Выполните `docker compose up --build -d`.
5. Откройте своего бота и отправьте `/start`.

Compose поднимает PostgreSQL, применяет миграции и запускает бот. Данные сохраняются
в Docker volume. `docker compose down` останавливает приложение с сохранением данных;
флаг `-v` удаляет базу. Логи: `docker compose logs -f bot`.
Пароль PostgreSQL в Compose предназначен для локального запуска, порт базы наружу не открыт.
Не запускайте несколько экземпляров polling-бота с одним токеном.

## Команды

- `/start` — регистрация или главное меню.
- `/profile` — профиль и лучшие результаты по килограммам в жиме, приседе, тяге и троеборье (с датами).
- `/record` или «Записать результат» — выбрать категорию.
- `/bench`, `/squat`, `/deadlift` — записать жим, присед или тягу.
- `/total` — записать троеборье: последовательно ввести присед, жим и тягу за один день.
- `/history` — выбор категории и история по 5 записей, от новых дат к старым. Под списком компактные кнопки с номерами записей. Нажмите номер, чтобы открыть карточку; «Изменить» открывает выбор поля, «Удалить» требует отдельного подтверждения. Изменения применяются только по кнопке «Сохранить изменения». Переходы обновляют одно сообщение, возврат сохраняет страницу истории. Масса тела показана в карточке, в списке — дата, вес штанги и Wilks.
- `/cancel` — отменить текущий ввод.

Бот работает только в личных сообщениях. При регистрации нужно указать ник, пол для
расчёта и массу. Для всех новых профилей часовой пояс задаёт `DEFAULT_TIMEZONE`
(по умолчанию Europe/Moscow); отдельного интерфейса его выбора пока нет.
Дата достижения автоматически ставится при начале ввода и доступна для изменения.
Будущие даты не принимаются. Точное время создания хранится отдельно в UTC.
После ввода веса штанги бот обязательно запрашивает массу тела на дату результата.
Для троеборья масса запрашивается один раз после ввода всех трёх движений и относится
ко всей записи. Масса из профиля автоматически не подставляется; профиль при этом
не меняется. Пол для расчёта копируется в запись, повторное подтверждение не создаёт дубликат.
Изменение массы в подтверждении относится только к записи, не к профилю.

## Формула

Используется **оригинальный Wilks**, идентификатор `wilks_original`, а не Wilks 2020.
Одиночные движения и троеборье хранятся раздельно. Баллы троеборья считаются по сумме
трёх весов с одной массой тела; округляется только отображаемый итог.
Для сохранения троеборья обязательны все три положительных веса. Общая дата относится
ко всем трём движениям — пользователь указывает результаты, выполненные в этот день.
Автоматически из одиночных записей троеборье не собирается. Отдельные записи движений
при сохранении троеборья создаются автоматически (по одной на движение).
Они связаны с исходным троеборьем: изменение весов, массы и даты в троеборье обновляет
три записи; удаление троеборья удаляет связанные записи. Независимые записи остаются.
Из карточки связанного движения можно открыть троеборье для редактирования.
Коэффициенты: [отчёт British Powerlifting, раздел Wilks Formula](https://www.britishpowerlifting.org/documents/962_models_evaluation-i-2020.pdf).
Полином вычисляется без промежуточного округления, баллы в интерфейсе округляются до сотых.
Для первой версии приложение поддерживает массу 40–200 кг для мужчин и 40–150 кг для
женщин. Это явное ограничение приложения: вне диапазона расчёт не выполняется,
масса автоматически не подменяется. Вес штанги: 0,01–1000 кг, до двух знаков после запятой.

## Локальная разработка

Python 3.12+:

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
cp .env.example .env
# Укажите токен и DATABASE_URL доступной PostgreSQL в .env.
alembic upgrade head
powerlifting-bot
```

Проверки:

```sh
pytest
ruff check src tests migrations
```

Тесты используют временную SQLite и не требуют токена или работающей PostgreSQL.
Рабочая база — PostgreSQL. Миграции применяются отдельно от приложения.

## Архитектура и границы этапа

- `telegram/` — диалоги, кнопки и команды aiogram.
- `services.py` — регистрация, сохранение, история; не зависит от Telegram.
- `domain/` — проверка веса и чистая функция Wilks.
- `db/` — модели SQLAlchemy; `migrations/` — миграции Alembic.
- `config.py` — настройки из окружения.

Изменение профиля — следующий этап. Лучшие результаты по килограммам уже доступны
в профиле и пересчитываются после редактирования или удаления записей. Рекорды движений
учитывают связанные записи троеборья; рекорд троеборья берётся только из одной полной
записи, а не из суммы личных рекордов разных дней. Данные и версия формулы для их реализации уже сохраняются.
Незавершённые диалоги хранятся в памяти: после перезапуска нужно начать ввод заново,
сохранённые профили и результаты остаются в базе. Для нескольких экземпляров потребуется
общее хранилище состояний и переход с polling на webhook.

## Обновление существующего бота

Миграция `0002` добавляет таблицу троеборья, `0003` — связи с одиночными движениями.
Для уже сохранённого троеборья миграция автоматически создаёт три связанные записи.
Старые профили и независимые результаты сохраняются. Для обновления кода и применения миграции:

```sh
docker compose build
docker compose run --rm migrate
docker compose up -d bot
```

В Telegram отправьте `/start`, чтобы получить новую кнопку «Записать результат».
Затем выберите жим, присед, тягу или троеборье. Старая кнопка «Записать жим» также
откроет выбор категории и обновит клавиатуру. В «Истории» категории тоже выбираются отдельно.
